## Default policies added during M0

| # | Policy |
|---|--------|
| P12 | **Filename split**: the extension is everything after the **last** period, per spec. Two cases a Windows-only implementation never had to face get the sane reading (P1): a *leading* period belongs to the name (`.gitignore` has no extension, `.config.toml` has extension `toml`), and `.`/`..` never have one. "Process Extension" scope **does not apply** to a file with no extension — the operation is skipped for that file rather than being handed an empty subject, which would silently append to the name instead. *(Extended by **P100**, 2026-09-25.)* |
| P13 | **Rename never overwrites.** `std::fs::rename` silently replaces the destination on every platform; `Platform::rename` fails with `TargetExists` instead. Windows gets this atomically via `MoveFileExW` with no `MOVEFILE_REPLACE_EXISTING`. Unix probes then renames, which leaves a TOCTOU window — closing it needs `renameat2(RENAME_NOREPLACE)` plus a fallback for filesystems that reject it, scheduled with the rest of the executor in M1. *(Closed on Linux 2026-09-25 by **D201**: `renameat2(RENAME_NOREPLACE)`, falling back to `link` + `unlink` for a file when the filesystem refuses the flag. Only a folder on such a filesystem, and other Unixes, keep the probe and its window.)* |
| P14 | **Rename cycles are reported, not half-executed.** The M0 planner topologically orders renames so chains (`a`→`b`, `b`→`c`) execute correctly, and marks anything left in a cycle (`a`↔`b`) as `ConflictKind::UnresolvedCycle`. M1 replaces this with temp-name cycle breaking (P6); until then the failure mode is a blocked run, never a partial one. |

### P7 addendum — regex dialect, resolved by the M0 spike

Verdict and method: `docs/spikes/regex.md`. Tests: `crates/ren-core/tests/spike_regex.rs`.
**`fancy-regex` 0.19 is adopted.** 33 of 36 documented constructs are identical. Deviations:

| # | Construct | Behaviour | Impact |
|---|---|---|---|
| R1 | `\cx` control-character escape | Not supported; the pattern is rejected at compile time. | None — no supported platform allows control characters in a filename. |
| R2 | Octal escapes `\n` / `\nm` / `\nml` | Not supported. The backreference half of the documented rule works; the octal fallback does not. | None, same reason. `\xnn` covers byte values. |
| R3 | `\w` `\d` `\s` `\b` | Unicode-aware, where JScript is ASCII-only. | Deliberate widening — JScript itself is ASCII-only. `PatternOptions::unicode = false` restores exact JScript semantics if a per-op switch is ever wanted. |

Also, `fancy-regex` supports lookbehind, which JScript does not — a harmless superset, but patterns written here may not run under a strict JScript engine.

Two wrapper-level fixes were required and are implemented in `ren-core/src/regex_flavor.rs`:

1. **`$1` followed by text.** Rust reads `$` plus the longest word-character run as a group name, so `$1x` means group `1x`, which does not exist, and the *whole replacement silently becomes empty*. `translate_replacement()` rewrites `$1`–`$9` to `${1}`–`${9}` and escapes every other `$`, restoring JScript's one-digit rule.
2. **`replace_all` panics** on backtrack-limit overflow (it is `try_replacen(..).unwrap()`). Everything goes through the fallible API; the overflow becomes `RegexError::TooSlow`, the per-row error P7 promises. The default budget is 100 000 steps, a tenth of `fancy-regex`'s own default, because this runs per file per keystroke.

Reassuring finding: `fancy-regex` delegates to the linear-time `regex` engine aggressively, so the textbook exponential patterns (`(a+)+$`, `(a|aa)+(?=c)`) never reach the backtracking VM. Only a backreference *to a repeated group* does.

## Default policies added during M1

| # | Policy |
|---|--------|
| P15 | **Positions count Unicode scalar values, not bytes**, and saturate rather than erroring. Zero-based: position 0 points to before the first character. Counting backwards converts to a forward index, so backwards position 0 is the very end — which is what the shipped "Add suffix to end of filename" preset (`Add '<Ask>' at pos 0 from ending`) relies on. The `delete = 999` idiom works because over-long counts truncate. |
| P16 | **`rANdOm` casing is seeded from the operation's config**, so a preview and the execute that follows it can never disagree, and a re-run reproduces the same names. An unseeded generator could not promise either. |
| P17 | **Swap Mode is ignored in regex mode as well as with wildcards.** Excluding wildcards alone is the obvious reading, but the same reasoning applies to a pattern, which cannot be turned back into the literal text it matched. Swap Mode performs a single simultaneous pass, so replaced text is never re-read by the other direction. *(Extended by **P102**, 2026-09-25.)* |
| P18 | **Space Trimming's stage order is fixed**: underscores→spaces, then maintain-space insertion, then shrink-multiple, then trim the ends. The options say nothing about their own order, and any other order leaves observable double spaces or an inserted space stranded at the edge. *(Extended by **P103**, 2026-09-25.)* |
| P19 | **Wildcards are a search everywhere except the include filter, where they are a mask.** A pre-processor section match wants the search reading: `is*` over `Batch Renamer is fantastic!` should pick out `is fantastic!`, the text from the first `is` on. An include filter wants the mask reading: `hello*` is only worth typing instead of plain `hello` if it means *starts with*. Plain strings stay "contains" in both, and a regex stays a search, since the user has `^` and `$`. *(What the mask is tested against — stem, whole name, path — is **D178**.)* |
| P20 | **The pre-processor narrows whatever slice the scope gave it.** It never sees the extension whenever the step is scoped to the name, and with `scope = "both"` it can reach the extension. A consequence of uniform scoping, and a useful one. |
| P21 | **Case-insensitive substring search never folds the haystack and reuses the offset.** Case folding changes byte lengths (`İ` is 2 bytes and folds to 3, `ß` folds to `ss`), so the hit lands mid-character and slices the wrong text — or panics. Offsets stay anchored to the source by comparing folded characters while walking the unfolded string. |

## Locked during M3 (2026-08-15, implementation session)

| # | Decision | Rationale |
|---|----------|-----------|
| D28 | **No serial finalize pass.** `docs/DESIGN.md` Part 1 §4 planned to emit placeholders for stateful tags during the parallel pass and substitute them in a second serial pass over every file, in visible order. That pass is replaced by a cheap serial **pre**-pass (`RunContext::build`) that resolves the counter sequence and its width, the `<Ask>` answers, the clipboard, `<NumFiles>` and the run's timestamp before evaluation starts. | Every tag that looks stateful turns out to be a pure function of the **input** listing. `<Counter>`'s resets read the entry's own folder and name, never a transformed one, so the whole sequence is `fn(&[FileEntry]) -> Vec<i64>`; auto-padding needs only the largest value in it; `<Rnd*>` is seeded (P16); `<Ask>`/`<Clipboard>` are collected once per run, which DESIGN itself specifies. So evaluation stays fully parallel and order-independent, which is also what keeps `evaluate_all` testable as a pure function. *(Clarified by **P106**, 2026-09-25.)* |
| D29 | **An unrecognised tag is a compile error, not an empty string.** `Template::compile` fails with the offending `<…>` and its byte range; the editor shows it while it is being typed. A tag from a family we recognise but have not built (`<Artist>`, `<Exif-…>`, `<PdfPages>`, `<DirFiles>`) says *that*, by name. | Rendering an unknown tag as nothing is how a folder of music ends up named `.mp3` across a batch — one typo, a thousand files, and the only clue is in the preview the user did not read. Naming the deferred families separately also means a user who types a real tag is told when it is coming rather than that it does not exist. *(Amended by **D182**, 2026-09-25.)* |
| D30 | **Date formats render fixed, sortable output, not the system locale.** Named formats resolve to fixed strings (`Short Date` → `yyyy-mm-dd`, `Long Time` → `Hh.Mm.Ss`); the time separator `:` renders as `.` and the date separator `/` as `-`. | The same job file then produces the same filenames on every machine, which is the whole point of a job file. And a date can never emit `:` or `/`, both of which are illegal in a Windows filename — a locale-dependent formatter would produce names Windows will not accept from a default as ordinary as `Hh:Mm:Ss`. The ISO form is also the most useful, because a listing sorts correctly by it. *(Amended by **D180** and **D181**, 2026-09-25.)* |
| D31 | **`<\>` moves a file into a subfolder of its own directory, and a produced name may never escape upward.** `/` is the one canonical separator (never `\`, which is a legal character in a POSIX filename). The planner splits the produced name on it, validates **every** component through `NamingRules`, and emits `PlannedOp::CreateDir` for the folders that do not exist, parents first. Creations are journalled; undo removes only the folders it created, deepest first and only while they are still empty. | Implemented in M3 at the user's request rather than deferred to M5. It is the one tag that makes a rename a *move*, so it is an executor change wearing a tag's clothing, and the safety properties are the interesting part: an absolute path or a trailing separator leaves an empty component, `.` and `..` are refused on every platform, and a Windows drive letter trips over the illegal `:`. The M1 property test asserting that no operation produces a path separator is replaced by the stronger rule it stood in for — **a target never escapes the folder its file came from**. |

## Default policies added during M3

| # | Policy |
|---|--------|
| P25 | **`<FileMax-#>` and `<PathMax-#>` truncate the text the template produced**, once, at the end, counting characters from the right. `<PathMax>` counts the folder the file is in plus a separator. The tightest limit wins if several appear. What each limit means is plain; *where* it applies needed a rule, and the template's own output is the only length the tag can know. |
| P26 | **Tag positions follow P15**: zero-based, saturating, counting characters. `<Mid-0-3>` is the first three characters, so it equals `<Left-3>`; `<MidRev-3>` counts backwards from the very end, so it equals `<Right-3>`; and `<MidRev-a-b>` is order-free. A 1-based `Mid()` is the other convention on offer, but the operations' positions are zero-based (P15), and one convention across the app beats two. |
| P27 | **`<Name>`, `<Left-#>` and friends read the name as the pipeline has it so far**, not as it was on disk — the tag menu calls `<Name>` *Current filename*, and it means current. |
| P28 | **The three first-letter tags differ only on digits.** `<FLetter>` yields the first character if it is a letter and is otherwise *unavailable*; `<FLetterN1>` accepts a digit as itself; `<FLetterN2>` folds every digit onto `#`, the convention every music library uses for its numeric shelf. The tag menu names them *First letter in name*, *First letter incl. numbers* and *First letter incl. numbers subst.*, and this is what we take the three to mean. Listed in `docs/manual-checks.md` to be eyeballed. |
| P29 | **`<Size>` (Auto) is fixed, not locale-dependent**: the largest 1024-based unit that keeps the value at or above 1, at most one decimal, `B`/`KB`/`MB`/`GB`/`TB` with no space (`512B`, `1.5KB`, `3MB`). Same reasoning as D30. |
| P30 | **Zero Padding crops from the left.** The editor says a longer number *is cropped instead*, and something has to decide which end. Keeping the last `#` digits is the only reading that serves the stated purpose — `007` padded to 2 is `07`, not `00` — and it makes padding out and back idempotent for any number that fits. |
| P31 | **Re-Number does not round by default.** Rounding every result to a fixed number of decimals and keeping every digit were both defensible defaults; silently rounding is the more destructive of the two, so a result keeps its digits unless the card asks for *Round to*. Arithmetic runs on `rust_decimal`, so `0.1 + 0.2` is exactly `0.3`. |
| P32 | **"Only rename if all tags are available" is enforced per tag field.** A step whose template could not fill in a tag leaves the name alone; the other steps still run. Per-field is the granularity that keeps every operation a pure function of its own input. |

## Locked during M4 (2026-08-15, implementation session)

| # | Decision | Rationale |
|---|----------|-----------|
| D32 | **No "override stored global options" toggle.** The alternative snapshots every global option into each preset item and offers a checkbox to ignore them. We have nothing hidden to override: a preset stores exactly what the cards show. Per-card scope and filter are explicit on the card; the source-bar include filter is a **default** that a card with no filter of its own inherits, and the card says which it is using. | `docs/DESIGN.md` §3 already settles it — *"the global options only set defaults"* — and D19 made scope per-step by construction, so such a toggle has nothing left to mean. A user decision. |
| D33 | **One parser, two readings.** `Document::parse` reads the D18 schema; `Job` requires at least one step and defaults `[source]`; `Preset` requires a name, allows zero steps, and never carries `[source]` — importing a file that has one keeps the pipeline and *reports* the drop. | A job file brings its own source; a preset borrows the caller's. That is one sentence a user can hold, and it is the only difference. Keeping it out of the grammar is what lets `examples/cleanup.toml` import as a preset unchanged, which is the whole point of D18's shared schema. Zero steps is legal because the **New** button creates an empty preset. |
| D34 | **Load replaces the pipeline *and* its run settings; Append adds only the operations.** | The counter, parts and tag policy are part of what was saved, so loading takes them. Appending does not: inheriting someone else's counter start when you meant to add two operations is a surprise you would only notice after renaming. |
| D35 | **The preset writer omits every value that equals its default.** Provably lossless — the whole schema is `#[serde(default)]` — and it is what makes a saved preset read like one a person wrote. Its most useful consequence: a Batch Replace card still holding the shipped 51 rules (D27) serialises as *absence*, and one the user has edited serialises in full. | A preset that embeds its rules is portable; one that points at a global list renames differently on someone else's machine. The trade-off is resolved per preset, by the user's own action, with no toggle to explain. `rules = []` stays expressible and distinct from absence, so "no rules" is sayable. |
| D36 | **`scope` defaults per operation**: the name for everything except Free Format, which defaults to both. | Free Format's canonical use forces it — `<Parent>_<FullName>` over `May09/0001.jpg` must give `May09_0001.jpg`, and scoped to the name the engine would put `.jpg` back on the end of a pattern that already carries it. The writer always spells `scope` out, so a saved preset is never ambiguous about it. |

## Default policies added during M5

| # | Policy |
|---|--------|
| P41 | **Undo's value-staleness check has a two-second tolerance, and never compares `accessed` or `archive`.** FAT rounds a written timestamp to two seconds and exFAT to ten milliseconds; a check demanding equality would report every file on such a volume as "changed by something else" and then refuse to undo anything on it. `accessed` is excluded because reading a file updates it — including, on some systems, the `get_times` call doing the checking — and `archive` because the OS sets it on any write and every backup tool clears it. Both are still *restored*; they are simply not evidence. |
| P42 | **Clearing the read-only bit on Unix grants the owner write and nobody else.** `Permissions::set_readonly(false)` sets all three write bits, so a 0644 file round-tripped through set-then-clear came back 0666 — and that round trip is exactly what "undo restores the previous attributes" does. Undo of attributes on Unix is lossy by construction (four bools cannot describe a mode), but with this the loss is always in the narrowing direction. |
| P43 | **An attribute already at the value being asked for needs no capability.** P5 forbids silently failing to make a change the user asked for; there is no change here to fail at. Without it, reading a dotfile's attributes and writing them back — the undo path — fails on every dotfile on Linux, because `hidden` is readable from the leading dot but not writable. Un-hiding a dotfile is still a real change and still fails loudly. |
| P44 | **An action's `effect` may read files but never writes, and anything expensive goes behind a process-wide, mtime-keyed cache.** `<Crc32>` already opens files from the parallel evaluation pass and declares it through `TagNeeds::FILE_CONTENT`; the Exif date source does the same. `Cached` alone cannot serve — `to_step` clones, and a clone resets it by design (D21) — so without the second layer a folder of 10 000 photographs would be opened once per keystroke. *(Clarified by **D184**, 2026-09-25.)* |
| P45 | **A file with no Exif date is a row left alone, never an error.** Not an image, no APP1 segment, a blank value and a malformed one are the same fact to a renamer. P4 stops the whole run on any row error, so calling it one would make a folder of 500 photographs with three PNGs in it unrunnable. |
| P46 | **Actions run after every rename, never interleaved.** A file caught in a rename cycle only reaches its final name at the very end (P6), so "immediately after that file's rename" would act on `__renameit-tmp-0`. Running last is also what hands undo the property its reverse walk needs: the action is reverted while the path the journal recorded still resolves, and only then is the rename taken back. |
| P47 | **A component mask that is not all-on needs the file's previous value**, and a stamp the filesystem never reported is a reportable row rather than a guess. The same reading P12 gives an extensionless file under `Scope::Extension`. |
| P48 | **An ambiguous local time takes the earlier of the two; a time daylight saving skips is reported, never nudged.** A preview has to be reproducible, so "whichever" is not an answer a plan can be built from; and quietly writing an hour other than the one asked for is the kind of thing nobody finds until much later. |

## Default policies added during M6

| # | Policy |
|---|--------|
| P49 | **A metadata reader answers for anything it can open, even with nothing to say.** Audio with no tags still has a duration and a bitrate, which come from the sound rather than from anything anybody wrote — so the file answers and the individual *tags* report themselves absent. Only a file that is not readable audio at all is `None`. |
| P50 | **Every reader is gated on a minimum size, set at the smallest thing that could possibly be real.** The perf corpus is ten thousand zero-byte `.mp3` files and without a gate a music pipeline over it is ten thousand futile parses per keystroke. The gate is 16 bytes, not a convenient 128: a threshold that rejects a legitimate file to save time on an illegitimate one is a bug waiting for somebody with a very short tag, and its failure mode is indistinguishable from "no tags". |
| P51 | **The folder peek takes the first file *by name* that yields something**, not the first the directory happens to list and not the first whose extension matches. `read_dir` order differs between filesystems and between two runs, and a folder has to rename to the same thing twice; a cover image with no Exif must not veto the photograph beside it. Shared by both readers so they cannot disagree about what "first" means. |
| P52 | **A metadata cache's capacity must exceed the listing sizes the app is designed for.** These caches clear *wholesale* when full rather than evicting least-recently-used, so a capacity below the working set is worse than useless: a 10 000-file folder against a 1 024-entry cache clears it ten times per pass, serves almost no hits, and still pays to build every key. Found by a parse counter, not a stopwatch — the planner's own work dominates the wall clock either way, so a timing ratio cannot tell a warm cache from a busy machine. The same flaw was latent in the Exif cache at 4 096. |
| P53 | **A file with *none* of a pattern's tags is left alone, rather than renamed to the pattern's punctuation.** `<Artist> - <Title>` over an untagged file renders `" - "` — and over a *folder* of untagged files it renders `" - "` for every one of them, so they all collide and P4 blocks the run with a message about duplicate targets that says nothing about the real problem. Leaving them alone says the true thing: they have no tags to rename from. A file with *some* tags still renames, because that is what was asked for and *"only rename if all tags are available"* is how a user says otherwise. *(Amended by **P104**, 2026-09-25.)* |
| P54 | **A track value that is not a plain number is skipped and *reported*, never written.** lofty parses the track numerically on the way out and what it does with anything else is neither consistent nor safe: on an MP3 `"3/12"` and `"A1"` are dropped, on a FLAC `"3/12"` becomes `"3"` and `"A1"` survives, and over a tag that already holds a numeric track a non-numeric value is written as **`0`**. A user mapping a filename part to Track on a vinyl rip would zero a whole album, silently, with no undo. The value is normalised in our code — digits only, leading zeros stripped — or the field is skipped, and the skip reaches the preview row because P5 forbids silently failing to make a change the user asked for. |
| P55 | **An enabled field that renders to *nothing* is skipped without comment; one that is *rejected* is reported.** The two look alike and are not: an empty box is a card the user is still filling in (P34), while a rejected value is a change that was asked for and refused. Writing the empty one would be worse than either — lofty's behaviour for an empty value is to **drop** the field, so "enabled but blank" would delete exactly what the unticked box promises to leave intact. |
| P56 | **Whether a file is music enough to touch is decided on its *name* in the preview and on its *content* in the executor.** `effect()` runs once per file per keystroke and is called every frame by `OpKind::problem()` against a synthetic path, so it may not open anything; the extension is the cheap gate, and a file it excludes is a row left alone rather than an error (P45) — a folder of 500 tracks with a `cover.jpg` in it has to run. The executor then decides the real format from content, never from the extension, because lofty's two paths disagree: for Musepack SV4-6 the extension says Musepack and the content says MPEG, and a save always verifies from content. |
| P57 | **Remove Tags ships with all three boxes clear.** Absence of a key in a job file must never mean "yes" in an operation that cannot be taken back. |

| P61 | **Anything that depends on the wall clock is tested off UTC.** CI's Linux job runs the suite under `TZ=Asia/Kolkata`. A half-hour offset also catches code that assumes offsets are whole hours. | P62 | **A reserved character in a produced name is refused, not substituted.** Automatically substituting the nine characters `/ * " \ ? : < > \|` from an editable table is the alternative; `ren-platform/src/naming.rs` validates and rejects instead, so the row becomes `ConflictKind::InvalidName` and P4 blocks the run until it is fixed.
